## 二、tool_registry.get_schemas() 详解

### 2.1 代码位置
**tools/registry.py:80-87**

```python
def get_schemas(self) -> List[Dict[str, Any]]:
    """
    获取所有工具的OpenAI schemas

    Returns:
        schemas列表
    """
    return [tool.get_schema() for tool in self._tools.values()]
```

### 2.2 tools 是什么内容

`tools` 是一个 **List[Dict[str, Any]]**，即字典列表，每个字典遵循 OpenAI Function Calling 的 schema 格式。

#### 示例数据结构：

```python
[
    {
        "type": "function",
        "function": {
            "name": "get_stock_quote",
            "description": "获取一只或多只A股股票的实时行情数据，包括价格、涨跌幅、成交量等",
            "parameters": {
                "type": "object",
                "properties": {
                    "codes": {
                        "type": "array",
                        "items": {"type": "string"},
                        "description": "股票代码列表，如 ['600036', '000001']"
                    }
                },
                "required": ["codes"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "calculate_indicators",
            "description": "计算A股股票的技术指标，包括MA、RSI、MACD、BOLL、KDJ等",
            "parameters": {
                "type": "object",
                "properties": {
                    "code": {
                        "type": "string",
                        "description": "股票代码"
                    },
                    "days": {
                        "type": "integer",
                        "description": "K线数据天数",
                        "default": 60,
                        "minimum": 30,
                        "maximum": 365
                    }
                },
                "required": ["code"]
            }
        }
    }
    # ... 更多工具
]
```

### 2.3 为什么是这个内容

这个格式是 **OpenAI Function Calling API 的标准要求**：

1. **type**: 必须是 `"function"`，表示这是一个可调用的函数
2. **function**: 包含函数的元数据
   - **name**: 函数的唯一标识符（英文，无空格）
   - **description**: 函数的自然语言描述，LLM 据此决定何时调用
   - **parameters**: JSON Schema 格式，定义参数的类型、描述、约束等

#### 设计原因：

| 设计决策 | 原因 |
|---------|------|
| 使用 OpenAI Function Calling 格式 | 这是与 LLM 交互的行业标准，支持工具调用决策 |
| 每个工具提供 description | LLM 需要理解工具功能才能正确选择 |
| 参数使用 JSON Schema | 提供类型安全、参数验证、自动补全能力 |
| required 字段 | 明确哪些参数是必须的，LLM 必须提供 |

#### 步骤 5: 处理 Tool Calls
**core/agent.py:188-240**

```python
async def _handle_tool_calls(self, response: Any, messages: List[Dict]) -> str:
    message = response.choices[0].message
    tool_calls = message.tool_calls  # 获取 LLM 要求的工具调用

    for tc in tool_calls:
        tool_name = tc.function.name           # "analyze_stock"
        tool_args = json.loads(tc.function.arguments)  # {"code": "600519"}

        # 执行工具
        result = await tool_registry.execute(tool_name, **tool_args)
```

#### 步骤 6: 工具执行
**tools/registry.py:89-105**

```python
async def execute(self, name: str, **kwargs) -> Any:
    tool = self.get(name)        # 从 _tools 字典获取实例
    if tool is None:
        raise ValueError(f"工具 {name} 不存在")

    result = await tool.run(**kwargs)   # 调用工具
    return result
```

**tools/base.py:92-107**

```python
async def run(self, **kwargs: Any) -> ToolResult:
    """运行工具（带异常处理）"""
    try:
        self.logger.debug(f"执行工具 {self.name}: {kwargs}")
        result = await self.execute(**kwargs)   # 子类实现具体逻辑
        self.logger.debug(f"工具 {self.name} 执行完成")
        return result
    except Exception as e:
        self.logger.error(f"工具 {self.name} 执行失败: {e}")
        return ToolResult(success=False, error=str(e))
```

## 四、核心设计思想

### 4.1 为什么需要 ToolRegistry

| 优势 | 说明 |
|-----|------|
| **解耦** | Agent 不需要知道具体有哪些工具，只需调用 `get_schemas()` |
| **动态注册** | 可以在运行时添加/移除工具 |
| **统一管理** | 统一处理工具的执行、错误处理、日志记录 |
| **单例模式** | 确保整个应用只有一个工具注册表实例 |

### 4.2 为什么使用 OpenAI Function Calling

```
传统方式                    Function Calling
──────────                  ────────────────
Prompt 描述工具    →        结构化 schema
LLM 自由生成       →        LLM 输出结构化调用
手动解析结果       →        自动解析 arguments
```

### 4.3 异常处理流程

```
工具执行异常
    │
    ▼
Tool.run() 捕获异常
    │
    ▼
返回 ToolResult(success=False, error=str(e))
    │
    ▼
Agent 将错误信息传给 LLM
    │
    ▼
LLM 生成友好的错误提示
```

## 六、总结

### 一句话概括

> `tool_registry.get_schemas()` 返回 **OpenAI Function Calling 格式的工具定义列表**，让 LLM 能够理解有哪些工具可用、每个工具做什么、需要什么参数，从而智能地决定何时调用哪个工具。

### 调用流程口诀

1. **注册** - Agent 初始化时注册所有工具到 Registry
2. **暴露** - 调用 `get_schemas()` 获取 OpenAI 格式的工具定义
3. **决策** - LLM 根据用户输入和工具描述，决定调用哪个工具
4. **执行** - Agent 解析 LLM 的 tool_calls，通过 Registry 执行对应工具
5. **整合** - 工具结果返回给 LLM，生成最终自然语言回复

### 设计亮点

- ✅ **符合 OpenAI 标准** - 直接使用官方 Function Calling API
- ✅ **类型安全** - 参数使用 JSON Schema 定义，支持验证
- ✅ **松耦合** - Agent 和具体工具实现解耦
- ✅ **可扩展** - 新增工具只需继承 Tool 基类并注册
- ✅ **异常安全** - 统一异常处理，不会导致 Agent 崩溃
